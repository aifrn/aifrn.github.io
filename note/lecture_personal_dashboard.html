강의 개요와 준비물

강의 개요

- 목표 : Claude Code에게 자연어 프롬프트로 지시하여 GitHub 페이지(ex: ai-lecture-lab.github.io)를 만들고, 실습 프로젝트 링크 + 시계 + 그래프가 있는 개인 대시보드로 발전시킨다. - 결과물 : https://[내깃허브아이디].github.io/ https://ai-lecture-lab.github.io/ - 저장소 : https://github.com/ai-lecture-lab/ai-lecture-lab.github.io - 소요 : 약 30~40분 (총 4단계)

준비물 (이미 다 준비되어 있음)

1. GitHub 계정 + 개인 깃허브 아이디 (예: ai-lecture-lab) 2. Git 설치 (git --version 으로 확인) 3. GitHub CLI(gh) 설치 및 로그인 4. Claude Code 설치 5. 빈 작업 폴더 (예: C:\dev\claudeCLI\ai-lecture-lab.github.io) -> 이 폴더에서 claude 실행

GitHub CLI 로그인 확인

gh auth login
gh auth status
"Logged in to github.com" 이 나오면 준비 완료!
핵심 개념 먼저 알기

1) GitHub Pages 의 "사용자/조직 사이트"

- 저장소 이름을 반드시 <계정 또는 조직 이름>.github.io 로 만들어야 한다. - 예) 조직 이름이 ai-lecture-lab 이면 저장소 이름 = ai-lecture-lab.github.io 사이트 주소 = https://ai-lecture-lab.github.io/ - 이 이름 규칙을 지키면 main 브랜치의 루트(/)가 자동으로 배포된다.

2) 프로젝트 사이트

- 같은 조직 안에 다른 저장소(예: to-do-list)를 만들고 Pages를 켜면 https://ai-lecture-lab.github.io/to-do-list 처럼 하위 경로로 열린다. - 그래서 메인 대시보드에서 각 실습 프로젝트로 링크를 걸 수 있다.

3) 배포 반영 시간

- push 후 보통 1~2분 뒤에 반영된다. - 화면이 안 바뀌면 Ctrl + F5 (강력 새로고침).
1단계: 가장 단순한 HTML 페이지 만들고 배포하기

프롬프트

내 깃허브 id 는 ai-lecture-lab 이고, ai-lecture-lab.github.io 라는 이름을 가진
페이지를 만들려고 한다. 우선 아주 단순한 html 하나만 있는 페이지를 만들어서
보여줘. 깃 커밋 & 깃 푸시까지 진행해줘.
* 수강생은 ai-lecture-lab 을 본인 계정·조직 이름으로 바꿔서 입력.

Claude Code가 수행한 작업

1. 현재 폴더 상태, git 설치, gh 로그인 상태, 원격 저장소 존재 여부 확인 -> 저장소가 아직 없음을 확인
gh auth status
gh repo view ai-lecture-lab/ai-lecture-lab.github.io
2. 조직이 실제로 존재하는지 확인
gh api orgs/ai-lecture-lab
3. index.html 작성 (제목 + 환영 문구, 화면 중앙 정렬) 4. 로컬 저장소 생성 -> 커밋 -> GitHub 저장소 생성 + push 를 한 번에 진행
git init -b main
git add index.html
git commit -m "Add initial index.html"
gh repo create ai-lecture-lab/ai-lecture-lab.github.io --public --source=. --remote=origin --push
5. Pages 배포 상태 확인
gh api repos/ai-lecture-lab/ai-lecture-lab.github.io/pages

포인트

- "커밋 & 푸시까지" 라고 명시하면 Claude가 저장소 생성부터 배포까지 끝낸다. - 저장소가 없으면 gh repo create 로 만들어 준다 (Public 이어야 무료 Pages 가능). - "아주 단순한 html" 이라고 지정했으므로 최소의 토큰으로 최소 기능만 가진 HTML 을 보여준다.

2. 클로드 활용 스네이크 게임
3. 개인 프로파일
4. 주식 일기
5. 4축 로봇암 시뮬레이터

Claude Code가 수행한 작업

1. index.html 을 카드형 그리드 레이아웃으로 변경 2. 6개 카드 각각에 번호(01~06), 제목, "준비 중" 배지 표시 3. 아직 링크가 없는 카드는 클릭이 안 되도록 처리 - href="#" - class="project_card is_pending" (CSS: pointer-events: none) - aria-disabled="true" (접근성: 비활성 상태 알림) 4. 커밋 & 푸시
git commit -m "Add 6 project placeholder cards"
git push

포인트

- "아직 링크는 작동하지 않는 것으로" 라는 조건을 주면 자리만 잡아 두고 나중에 주소만 채우는 구조로 만들어 준다.

4단계: 개인 대시보드로 확장하기 (시계 + 그래프 + 링크 연결)

프롬프트

1번 할일 목록 리스트 링크 연결해줘 . 링크는
"https://ai-lecture-lab.github.io/to-do-list" 이다.
개인 대시보드 형식으로 프로젝트 연결 링크와 함께 현재 시간을 보여주는 시계를
추가해줘.
  우선은 그래프로 파이 챠트와 꺽은선 그래프를 데모용으로 그려줘. 나중에 그
  자리에 다른 값을 넣을수 있게 자리 확보해줘. 적당한 선에서 개인 대시 보드로
  보여질수 있는 값, 수치, 문구, 그래프 등을 넣어줘.

Claude Code가 수행한 작업

1. 화면 구성을 대시보드 형태로 재설계
+---------------------------------------+---------------+
|  인사말 (시간대별로 바뀜)             |  시계/날짜    |
+---------+---------+---------+---------+---------------+
| 학습시간 | 연속학습 | 완료실습 | 커밋 수  |  <- 수치 타일 4개
+-------------------+-----------------------------------+
|  파이 차트        |  꺾은선 그래프 (최근 7일)          |
+-------------------+-------------------+---------------+
|  실습 프로젝트 6개 + 연결 진행률 바   | 오늘의 문구   |
|                                       | 이번 주 목표  |
+---------------------------------------+---------------+
2. 시계: setInterval 로 1초마다 시:분:초, 날짜, 요일 갱신 3. 그래프: Chart.js (CDN) 사용
<script src="https://cdn.jsdelivr.net/npm/chart.js@4.4.1/dist/chart.umd.min.js"></script>
4. 모든 값을 dashboard_data 라는 객체 하나에 모아 둠 -> 나중에 이 객체의 값만 바꾸면 화면 전체가 갱신된다. 5. 1번 프로젝트에 링크 연결 -> "바로가기 →" 로 표시, 새 탭으로 열림 6. 반응형(모바일 폭) + 다크 모드 지원 7. 커밋 & 푸시 후, 연결한 링크가 실제로 열리는지(HTTP 200) 확인

- index.html 의 projects 에서 2번 url 을 본인 스네이크 게임 주소로 바꾸고 git add / commit / push 해 보기.

[과제 2] 같은 작업을 Claude Code에게 시키기

[과제 3] 그래프를 실제 데이터로 바꾸기

꺾은선 그래프를 이번 주 실제 학습 시간으로 바꿔줘.
월 1시간, 화 2시간, 수 0.5시간, 목 3시간, 금 1시간, 토 4시간, 일 2시간이야.
데모 배지는 지워줘.

[과제 4] 나만의 위젯 추가

대시보드에 D-day 카운터를 추가해줘. 기준일은 2026-12-31 이고 제목은
"강의 종료까지" 로 해줘. 다른 패널과 디자인을 맞춰줘.
좋은 프롬프트 작성 요령 (이번 실습에서 배운 점)
1. 배경을 먼저 알려준다 "ai-lecture-lab 은 내 개인 organization 이다" -> 저장소 이름 규칙을 맞춰 줌 2. 범위를 정해 준다 "아주 단순한 html 하나만" -> 과하게 만들지 않음 3. 끝까지 할 일을 명시한다 "깃 커밋 & 깃 푸시까지" -> 배포까지 한 번에 끝남 4. 미래 확장을 말해 둔다 "나중에 그 자리에 다른 값을 넣을 수 있게" -> 데이터를 한곳에 모은 구조로 설계 5. 정도를 정해 준다 "적당한 선에서" -> 필요한 만큼만 추가 6. 단계적으로 키운다 단순 페이지 -> 링크 자리 -> 대시보드 순서로 나누면 결과를 확인하며 수정하기 쉽다.
문제 해결 (FAQ)

Q. push 했는데 사이트가 안 바뀌어요.

A. 1~2분 기다린 뒤 Ctrl + F5. 빌드 상태는 아래 명령으로 확인.
gh api repos/<조직>/<조직>.github.io/pages/builds/latest

Q. 404 가 떠요.

A. 저장소 이름이 정확히 <조직>.github.io 인지, index.html 이 루트에 있는지, 저장소가 Public 인지 확인.

Q. 그래프만 안 보여요.

A. Chart.js 를 인터넷(CDN)에서 불러오므로 인터넷 연결을 확인. 그래프 외 나머지 화면은 정상 동작하도록 만들어져 있다.

Q. gh 명령이 실패해요.

A. gh auth status 로 로그인 확인. 안 되어 있으면 gh auth login.

Q. 프로젝트 링크가 404 예요.

A. 해당 프로젝트 저장소(예: to-do-list)에서도 Settings > Pages 가 켜져 있어야 한다.
